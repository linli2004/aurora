# AUR-027 — Automatic Library Refresh

## Status

Implementation candidate for local validation.

## Intent

AUR-026 remembers library roots and supports manual **Rescan all**. AUR-027
turns those roots into a living local library: Aurora refreshes them once after
startup and reacts to filesystem changes while the application remains open.

The refresh remains local-first and reuses the existing scan, stable Track
identity, preferred-source projection and missing-source reconciliation paths.

## Scope

- Add `LocalLibraryWatcher` around `QFileSystemWatcher`.
- Watch each readable directory discovered beneath remembered library roots.
- Coalesce bursts of filesystem events through a single-shot debounce timer.
- Run a background full-root refresh when a watched directory changes.
- Run one delayed background refresh after startup when roots are remembered.
- Rebuild the recursive watch set after every successful complete scan.
- Preserve scan cancellation and prevent concurrent scans.
- Queue one follow-up automatic refresh when a change arrives during scanning.
- Expose automatic-refresh activity and watched-directory count from
  `LocalLibraryService`.
- Add deterministic watcher normalization and debounce tests.

## Runtime Flow

```text
remembered roots
    ↓
startup delayed refresh
    ↓
recursive scan + stable Track/TrackSource upsert
    ↓
recursive readable directories registered with QFileSystemWatcher
    ↓
directory change burst
    ↓
900 ms debounce
    ↓
background full-root refresh
    ↓
missing-source reconciliation + Tracks refresh
```

A full refresh is intentionally reused instead of introducing a second
incremental indexing path. This keeps AUR-016 through AUR-026 identity and
availability behavior authoritative.

## Acceptance Criteria

1. Starting Aurora with remembered roots automatically scans them in the
   background without user interaction.
2. Adding a supported audio file to a watched folder updates Library and Tracks
   after the debounce window.
3. Moving or removing a source triggers missing-source reconciliation.
4. Multiple filesystem events generated by one operation result in one refresh.
5. A change arriving during a scan queues at most one follow-up refresh.
6. New nested directories discovered during refresh are watched afterward.
7. Duplicate content remains one projected Track.
8. Manual **Add folder**, **Rescan all** and **Cancel scan** continue to work.
9. All existing tests and the new watcher tests pass.

## Out of Scope

- Per-file incremental database mutations.
- Linux inotify overflow recovery and production-scale watch sharding.
- User-facing automatic-refresh preferences.
- Removing or reordering remembered roots.
- Automatically detecting the reappearance of an unavailable root whose own
  directory watch no longer exists.
- Interactive relink selection.
